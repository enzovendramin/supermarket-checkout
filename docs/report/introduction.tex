\chapter{Introduction}
\label{ch:introduction}

This report documents the design and implementation of a \emph{supermarket
checkout system} developed in Java for the course \emph{2EL1520 --- Génie
logiciel orienté objet}. The system processes the items a customer buys at a
checkout, computes the corresponding bill, handles the bank-card payment, and
keeps the shop's inventory up to date in real time.

\section{Context and Objectives}
A supermarket checkout system is a natural setting for object-oriented design:
it brings together several collaborating components --- the \emph{cash register}
(which records the bought items and computes the total bill), the
\emph{customer} (who may adhere to a discount plan and request home delivery),
and the \emph{bank payment system} (which authorises the card transaction). Each
component has clear responsibilities and well-defined interactions.

The objective of this work is therefore twofold: to implement the full set of
functional requirements, and to do so with a clean, pattern-driven design that
remains open to extension. This report emphasises \emph{why} the code is
structured the way it is, and shows explicitly that every required feature has
been implemented and tested.

\section{Scope and Deliverables}
The deliverables associated with this project are:
\begin{itemize}[nosep]
  \item the Java implementation of the supermarket checkout system, built with
  Maven and tested with JUnit~5;
  \item an initial configuration file (\code{my\_supermarket.ini}) and
  end-to-end test scenarios executed through the command-line interface;
  \item the UML models (class, use-case and sequence diagrams);
  \item this report.
\end{itemize}
The source code is hosted at
\url{https://github.com/enzovendramin/supermarket-checkout}. The repository
offers two runnable versions: a \emph{specification version} (tag \code{v1.0}),
containing exactly what the instructions require, and a \emph{final version} (the
\code{master} branch), which adds the optional extensions described in
Part~\ref{part:extensions}.

\section{Report Structure}
The report is organised in two parts. \textbf{Part~\ref{part:specified}} covers
the \emph{specified system}: it recalls the requirements and the design
decisions they induced (Chapter~\ref{ch:requirements}), presents the
architecture, the design patterns and the UML models
(Chapter~\ref{ch:architecture}) and describes the testing
(Chapter~\ref{ch:testing}). \textbf{Part~\ref{part:extensions}} is dedicated to
the optional extensions built on top of the specified baseline. The report ends
with a design analysis and conclusion, followed by appendices containing the
complete class diagram and the build instructions.
